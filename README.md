# YTF — пайплайн публикации type beat на YouTube

Всё на Rust: рендер, работа с YouTube API, веб-интерфейс. Один бинарник,
без Python. Работает на Windows и macOS (ffmpeg ставится отдельно).

---

## Что делает

1. Сканирует `People/<человек>/<канал>/`
2. По каждому каналу проверяет через API, есть ли уже видео на сегодня
   (учитывает и опубликованные, и отложенные)
3. Если день свободен — берёт трек и картинку, которых ещё не использовал
4. Рендерит 1080p с «выходом из темноты»
5. Заливает через YouTube Data API с отложкой на 22:00 по Омску
6. Проверяет, не взял ли YouTube чёрный кадр обложкой — если взял, ставит свою
7. Удаляет файл, пишет в журнал

## Установка

Нужен ffmpeg. Положи бинарники сюда:

```
tools/ffmpeg/ffmpeg-<версия>/bin/ffmpeg.exe
tools/ffmpeg/ffmpeg-<версия>/bin/ffprobe.exe
```

Либо в PATH (`macOS: brew install ffmpeg`). Проверить:

```
ytf doctor
```

Сборка:

```
cd ytf
cargo build --release
```

Бинарник: `ytf/target/release/ytf.exe` (6.7 МБ)

## Структура папок

```
yt channels/
├── settings.json          настройки рендера и публикации
├── tokens.json            refresh_token'ы, ключ — имя папки канала
├── client_secret.json     OAuth-клиент Google Cloud
└── People/
    └── <человек>/
        └── <канал>/
            ├── _config.json     необязательно, переопределения для канала
            ├── music/           треки
            ├── pictures/        картинки И видео (для режима loop)
            ├── names/           шаблоны заголовков
            ├── description/     шаблоны описаний
            ├── tags_for_video/
            └── tags_for_description/
```

### `_config.json` (необязательно)

```json
{
  "title": "Columbina prod.",
  "enabled": true,
  "schedule": true,
  "mode": "random",
  "single_music": null,
  "single_pictures": [],
  "no_randomize": false,
  "publish_at": "22:00",
  "category_id": "10",
  "made_for_kids": false
}
```

**mode**:
- `random` — случайный трек + случайная картинка
- `single` — всегда `single_music` и `single_pictures` (релизный режим, без рандома)
- `loop` — вместо картинки крутится случайное **видео** из `pictures/`,
  палиндромом, конец ровно на последнем бите

## Команды

```
ytf doctor              проверить окружение
ytf library             список каналов и что в них есть

ytf tokens              проверить все токены (реальный запрос к Google)
ytf quota               показать расход квоты

ytf publish             опубликовать все каналы
ytf publish "<канал>"   один канал
ytf publish --no-upload отрендерить, но не загружать
ytf check-thumb <файл>  какие кадры система считает чёрными
ytf web                 веб-интерфейс на :3000
```

Глобальный флаг: `--root <путь>` — корень проекта.

## Квоты YouTube (важно)

По официальной документации (обновлено 15.09.2026):

- `videos.insert` — **отдельный бакет, 100 вызовов в сутки**, 1 единица за вызов
- `search.list` — такой же отдельный бакет, 100 в сутки
- всё остальное — общий бакет **10 000 единиц в сутки**
  (`thumbnails.set` = 50, `videos.list` = 1, `analytics.query` = 5)

Сброс — 00:00 по Pacific Time.

Отсюда: 50 каналов по 1 видео в день = 50 вставок из 100. Запас двойной.
**100 каналов = ровно лимит, без запаса.** Реальный потолок ~80.

Поставить свою обложку почти бесплатно: 100 штук = 5000 единиц из 10 000.

Локальный учёт ведётся в `state.json`, но реальные цифры показывает только
консоль Google: `console.cloud.google.com` → YouTube Data API v3 → Quotas.

## Настройки (`settings.json`)

### render
| Поле | По умолчанию | Смысл |
|---|---|---|
| `width` / `height` | 1920 / 1080 | разрешение |
| `fps` | 30 | кадров в секунду |
| `crf` | 22 | качество: меньше = лучше и больше |
| `preset` | veryfast | скорость кодирования |
| `audio_bitrate` | 160k | битрейт звука |
| `fade_from_black_secs` | 10.0 | «выход из темноты», 0 = выключить |
| `seamless_loop` | true | палиндром для режима loop |
| `crop_to_fill` | true | обрезать по центру, иначе чёрные поля |
| `black_frame_threshold` | 30 | p90 яркости ниже = «тёмный» кадр |
| `black_frame_flatness` | 12 | разброс p90-p10 ниже = «плоский» |

### publish
| Поле | По умолчанию | Смысл |
|---|---|---|
| `hour` / `minute` | 22 / 0 | время публикации по Омску |
| `timezone` | Asia/Omsk | часовой пояс каналов |
| `workers` | null | null = авто (ядра / 2) |
| `upload_retries` | 3 | попыток загрузки |
| `fix_black_thumbnail` | true | менять обложку, если YouTube взял чёрную |
| `delete_after_upload` | true | удалять файл после загрузки |
| `horizon_days` | 1 | дней вперёд |
| `stream_to_upload` | true | рендер сразу в загрузку, без записи на диск |

## Рандомизация

**По умолчанию — никакого рандома.** Берётся первый шаблон, теги в том
порядке, в каком лежат в файле, ничего не выкидывается.

Рандом включается **только галочкой** «Рандомизировать теги и описание»
(в веб-интерфейсе) или флагом `--randomize` (в CLI), и только на один запуск:

- перемешиваются теги
- выкидывается 10–25% тегов видео и 5–30% тегов описания

Зачем выбрасывать: YouTube сортирует теги по алфавиту, поэтому одна
перестановка не видна. Нужен именно выброс.

## «Выход из темноты» и обложка

Видео начинается с чёрного экрана и проявляется за `fade_from_black_secs`.
Проблема: YouTube по умолчанию берёт обложкой первый кадр, а он чёрный.

Решение — автоопределение:

1. Ждём, пока YouTube сгенерирует превью
2. Скачиваем его и считаем гистограмму яркости
3. Кадр считается плохим, если **одновременно**:
   - `p90 <= black_frame_threshold` (тёмный)
   - `p90 - p10 <= black_frame_flatness` (плоский, без деталей)
4. Если плохой — вырезаем кадр из середины и заливаем через `thumbnails.set`

Проверить на любом файле:

```
ytf check-thumb .work/video.mp4
```

Проверено на реальном рендере:

```
первый кадр      t=  0.1с  p10= 16 p90= 17 разброс=  1  ЧЁРНЫЙ -> менять
конец проявления t= 10.5с  p10=  4 p90= 97 разброс= 93  норма
середина         t= 63.2с  p10=  4 p90= 98 разброс= 94  норма
```

Одного среднего мало: JPEG на чёрном кадре даёт постоянный сдвиг (у нас
ровно 16 при настоящем нуле), поэтому среднее = 16 и «порог 12» не срабатывал.
Разброс перцентилей — надёжный признак.

## Скорость (замер на 8 ядрах, трек 207 сек)

| Вариант | Секунд | МБ |
|---|---|---|
| 8K 1fps (старый код) | 43.7 | 17.4 |
| **1080p 30fps + проявление** | **21.5** | **10.7** |
| видеоряд + палиндром | 27.2 | 10.3 |

Переход 8K → 1080p дал **2.2× быстрее и в 1.7–3.2× меньше файла**.

Внутри 1080p fps почти не влияет на скорость — время уходит в кодирование
звука и мукс, а не в кадры. Поэтому 30fps можно брать почти бесплатно.

## Защита от повторов

`used.json` хранит, что уже использовалось. Треки выбираются сначала те,
которые ещё не брались, потом наименее использованные. Картинки подбираются
так, чтобы не повторяться в паре с тем же треком. Работает между каналами
и между днями — даже если жанр один.

Сбросить: удалить `used.json`.

## Проблемы

**`invalid_grant` при проверке токена** — refresh_token мёртв. Причины:
- проект в режиме **Testing** → токен живёт 7 дней
- токен отозван
- токен выдан другому OAuth-клиенту

Лечение: `ytf auth "<папка канала>"`. Проверь в консоли Google, что consent
screen в режиме **Production** — иначе токены будут протухать каждую неделю.

**`403 insufficient authentication scopes`** — в токене нет `youtube.upload`.
Перевыпусти через `ytf auth`.

**`ffmpeg не найден`** — положи в `tools/ffmpeg/**/bin` или в PATH.

**`no channel` при проверке** — токен не от того аккаунта.
